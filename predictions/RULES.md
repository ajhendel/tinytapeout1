# The analysis rules, fixed before fabrication

This file is the half of the pre-registration that is not a number. The numbers
come out of the shipped build and are generated by `tools/prereg.py`; the rules
below are judgements, they cannot be generated, and they are the half that
decides what a number means.

Under the same rule as everything else in this directory: **committed before the
shuttle deadline, append only afterwards.** A correction is a new file that names
what it corrects.

A rule written after the data exists is not a rule, it is a choice. Every one of
these was written while the answer was unknown, which is the only time writing
them is worth anything.

## 1. How a raw capture becomes a delay

The exact procedure, so that nobody has to reconstruct it later:

1. Read the status byte on the MEASURING trial. `tdc_done` describes the last
   trial only; reading it after the readout trials reports that a readout trial
   measured nothing, which is true and useless.
2. Read the four tap bytes and the coarse byte on trials with `tdc_en` low, so
   that reading does not destroy the capture being read.
3. Convert the coarse byte from Gray to binary with `gray_to_bin()`. It is Gray
   on the wire. A host that reads it as binary agrees with the chip for counts 0
   and 1 and disagrees from 2 upward, which is the shape of mistake that passes
   a short test and corrupts a long measurement.
4. Decode with `tdc_reading()` in `harness/evofab/genome.py`. That function is
   the reference implementation and it is tested against synthesised captures in
   `harness/tests/test_tdc_decode.py`, including bubbles, boundary cases,
   saturation, a lost sampling branch and randomised bin widths.
5. Apply the bin width table from study 2 to turn a bin index into a time. Until
   study 2 is done, every number from this chip is quoted in raw tap counts and
   says so.
6. Subtract the per-tap stop selector offset from `tools/stop_tree.py` before
   fitting any per-site slope. The offsets are extracted from the shipped
   build's own SDF and are part of the submission artifacts.

## 2. Which readings are excluded, and the rule is the status

A reading is used if and only if `tdc_reading()` returns `VALID`. The other four
statuses are excluded, and the exclusions are counted and reported alongside
every result, because an exclusion rate is data.

| status | excluded | repeated |
|---|---|---|
| `NO_ARRIVAL` | yes | yes, up to the repeat budget |
| `COARSE_SATURATED` | yes | no. The configuration is out of range and that is the finding |
| `BOUNDARY_AMBIGUOUS` | yes | yes, immediately |
| `THERMOMETER_INVALID` | yes | yes, and if it recurs on the same tap the die is flagged |

`BOUNDARY_AMBIGUOUS` readings must never be averaged or interpolated. The two
candidates differ by a whole ring period, so the mean of them is a delay that
did not happen. Repeat the trial; the phase relationship to the coarse counter
is not stable between trials, so a repeat lands elsewhere.

**Predicted exclusion rate for `BOUNDARY_AMBIGUOUS`: 3 percent, plus or minus 2.**
Two guard taps out of the 64 in a ring period. A rate far outside that is itself
a finding about the coarse capture and is reported as one rather than absorbed.

**A die is excluded entirely** if any of these fail: the scan chain does not
shift its own length, the CRC does not gate a corrupted frame, the readout does
not report the expected instrument version and site count, or the safety trip
cannot be made to fire. Those are stage A of the bring up order and no result
from a die that fails them is reported at all.

## 2b. Two corrections applied before any fit, amended 2026-08-28

Both are extracted per-instance constants from the shipped build, both are
subtracted from raw readings before anything is fitted, and both are named here
rather than applied quietly in analysis code.

  - **The per-tap stop selector offset**, from `tools/stop_tree.py`. The tree
    that selects which fabric site stops the converter has equal logical depth
    and unequal delay, and the correction is what makes the per-site slope in
    study 8 a measurement of the sites rather than of the selector. The
    correction table is polarity dependent, because rise and fall through that
    tree differ by about six taps.
  - **The per-path launch and merge offset**, from `tools/char_offsets.py`. The
    depth series' four short points launch from tree branch 2 and its 32 stage
    point from branch 4, so a per-branch delay difference lands on the longest
    lever arm and biases the SLOPE, measured at 3.2 to 4.5 percent. **The
    corrected slope is the pre-registered one.** The uncorrected slope is
    recorded beside it, and the difference between them is predicted too, so
    that a die which disagrees with the correction is distinguishable from one
    that disagrees with the model.

Neither correction is allowed to grow after the deadline. If silicon says a
correction was wrong, that is a result and it is written as one, not folded back
into the analysis.

## 3. Repeats, and the precondition nobody can skip

`tools/tdc_range.py` prints the repeat count each comparison needs, from the
quantization variance of one tap. Those counts are part of the pre-registration.

**They assume the arrival time DITHERS.** Averaging beats quantization only if
the arrival moves across bin boundaries between trials. If it does not, every
trial returns the same code and no number of them helps: the mean of one
thousand identical readings is that reading.

So the dither is measured before it is relied on. Study 2's code density run
gives the distribution of arrival phases directly. If the measured dither is
smaller than one bin, **every comparison below one tap becomes an upper bound**
and is reported as one. That switch is made on the measurement, not on
convenience, and the rows it would affect are named in advance: the load ladder
pair, the input isolation pair, and the load series 0 against 1 sink.

## 4. Multiple comparisons, for the search

Study 9 searches up to a million configurations for disagreement between the
models and the silicon. A million configurations produce a best-of-a-million
disagreement whether or not anything real is there, and quoting that as a result
is the single easiest way to publish noise from this chip.

The rules, fixed now:

- **The finalist count is 50**, chosen before any search runs. Not the top
  however-many turned out to look good.
- **The baseline is a random search of matched size**, run on the same dies with
  the same budget, and its best-of-N disagreement is the null. The comparison
  that matters is the search's best against the random search's best, not
  against zero.
- **The test is on the holdout dies**, which no search has touched, and the
  significance threshold is Bonferroni corrected over the 50 finalists. A
  finalist that does not survive that correction is reported as not surviving
  it, in the same table.
- **The full finalist list is published, ranked, with every one's holdout
  result**, including the ones that failed. Publishing only the survivors is
  the same error one level up.

## 5. The die split

Dies are split as they arrive, before any measurement, by a rule that does not
look at any measurement.

- The split is **two thirds training, one third holdout**, minimum two holdout
  dies. With fewer than four dies in total there is no split and no transfer
  claim is made; the transfer study is recorded as not run.
- The assignment is by package serial, recorded in the reservation, committed
  before the first trial.
- The reservation is enforced by `harness/evofab/holdout.py`, which sits between
  the search and the device rather than inside the search loop, because a check
  inside the loop is a check that a second script written at midnight will not
  have.
- **The holdout is released once**, in public, with the reason recorded. There is
  no second holdout after that and no re-splitting.

## 6. What counts as confirming a model layer

Each quantity is predicted separately by each model layer we have: the released
Liberty view, Liberty plus extraction, and transistor-level SPICE where we ran
it. They are allowed to disagree with each other, and being wrong at one layer
does not indict another.

A layer is recorded as agreeing with silicon on a quantity if the measured value
falls inside the predicted interval. The intervals are stated in the generated
prediction files and their meaning is stated with them. **No interval is widened
after a measurement.** A prediction that turns out to be wrong is a result and is
the more interesting kind.

## 7. The one thing this chip is not allowed to report

Energy. There is one supply and one whole-chip current, so no per-block energy
number from this die can be attributed to a block. PLAN.md section 2 puts it out
of scope and this file repeats it because it is the claim most likely to be
attempted from an ammeter reading and a stopwatch.
